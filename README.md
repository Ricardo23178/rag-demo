# 课件问答 RAG Demo（Chroma + pypdf + DeepSeek）

把一份 94 页的课件 PDF 变成能追问、能给出页码出处的问答助手。重点不在"接个模型"，而在**文档清洗、切块策略和可评测性**。

## 架构

```
离线建库（跑一次）                          在线问答（每次请求）
PDF → pypdf 抽取文字                      提问 → BGE 向量化
    → 剔除页眉页脚模板行                        → Chroma 余弦检索 top-k
    → 按小节聚块 + 折行合并                     → 组装 Prompt（只依据资料）
    → BGE-small-zh 向量化                      → DeepSeek 流式生成
    → 写入 Chroma（带小节 / 页码元数据）        → 回答附 [小节 p.页码]
```

## 快速开始

```bash
pip install -r requirements.txt -i https://pypi.org/simple

# 1) 配置密钥（不要写进代码）
cp .env.example .env      # 填入 DEEPSEEK_API_KEY
set DEEPSEEK_API_KEY=sk-xxx        # Windows cmd
# export DEEPSEEK_API_KEY=sk-xxx   # bash

# 2) 建库（首次会下载 BGE 模型约 100MB，走 hf-mirror）
python ingest.py

# 3) 命令行问答
python rag.py

# 4) 网页界面
streamlit run app.py

# 5) 评测（不带 --llm 只评检索，不需要 Key）
python eval.py
```

语料放 `data/*.pdf`，支持多个文件一起建库。

## 关键设计（面试可讲的部分）

**1. 页眉页脚自动识别**
课件每页都有同一行页眉 `An Introduction to Database System`，94 页里出现 95 次。这类文本会进入几乎每个 chunk，导致「任何问题都能匹配到它」，是很典型的噪声特征污染。
处理方式：统计所有行在页面间的出现频率，超过页面数 50% 的行判定为模板行并剔除。本项目剔掉 1 行，原始 15,418 字符降到清洗后的可用文本。

**2. 按小节聚块，而不是固定字数硬切**
用正则识别 `7.1` / `7.1.1` 这类标题，把同一小节下的连续页合并成一块，元数据保留 `section` 和 `pages`。好处是引用能精确到「7.2.3 数据字典 p.40-47」，而不是只给一个页码。

**3. 折行合并**
PDF 里一句话常被排版拆成两三行（`构造（设` / `计）优化的…`）。规则：上一行没有句末标点、且本行不是列表项时接回上一行；短行用「：」「；」分隔，避免两句粘死。

**4. 碎块过滤**
纯目录页、只有图注的页面会切出几十字的碎片，对检索只增噪不增信。小于 120 字的块直接丢弃。

**5. BGE 的查询前缀**
中文 BGE 模型检索时，query 需要加指令前缀（`为这个句子生成表示以用于检索相关文章：`），否则召回明显下降。代码里用 `query_embed()` 处理。

**6. 为什么不用 DeepSeek 做向量化**
DeepSeek 只提供对话/推理接口，没有 embedding 模型。所以向量化用本地 `BAAI/bge-small-zh-v1.5`（fastembed + onnxruntime，CPU 可跑，约 100MB），DeepSeek 只负责生成。

## 评测结果

12 条人工问题，top_k=4（`python eval.py --llm`）：

| 指标 | 值 |
|---|---|
| hit@4 | 100%（12/12） |
| MRR | 1.000 |
| 回答覆盖关键词 | 12/12 = 100% |
| 检索延迟（中位数） | 8 ms |
| 端到端回答延迟 | 1.0 ~ 2.0 s（deepseek-chat，流式首字约 0.8 s） |
| 语料 | 94 页 → 14 个块 / 9,540 字 |

**拒答行为**（RAG 最容易被追问的点）：

| 提问 | top1 相似度 | 结果 |
|---|---|---|
| 索引优化有哪些策略？ | 0.495 | ✅ 回答「课件中未提及」，并说明缺什么 |
| 期末考试重点是什么？ | 0.426 | ✅ 拒绝编造考试范围 |

文档内问题的 top1 相似度普遍在 0.70 以上，文档外问题掉到 0.43~0.50。这个分布说明**相似度可以当拒答门控**（低于阈值直接回「未提及」，省一次模型调用），是后续可加的一层。

> 注意：语料只有 14 个块、问题又是按课件内容设计的，指标偏乐观。真实场景需要更大的语料和对抗性问题（同义改写、跨小节推理、答案不存在的问题）。

## 已知限制

- **图片内容检索不到**：课件里的 E-R 图、模式图是图片，`pypdf` 只能拿到图注，问「图 7.3 画了什么」会答不出。
- **符号字体导致列表项粘连**：部分项目符号是私有区字符，抽出来变空格，合并后会出现「存取效率高数据库存储空间的利用率高」这种粘连。彻底解决要换 PyMuPDF 拿坐标信息。
- **只做单轮检索**：多轮追问里的指代（「它有什么特点」）需要 query 改写，尚未实现。
- **扫描件不支持**：无文字层的 PDF 需要先 OCR。

## 后续可以做的

1. 混合检索：BM25（关键词）+ 向量，用 RRF 融合，缓解专有名词召回差。
2. rerank：`bge-reranker-base` 对 top-20 重排，换取精度。
3. 多轮改写：把「它」补全成实体再检索。
4. 换 PyMuPDF 抽取布局，修复列表粘连。
5. Docker 化 + 简单的检索命中率回归测试。
