# 课件问答：RAG + Agent 工具调用（Chroma + pypdf + DeepSeek）

把一份 94 页的课件 PDF 变成能追问、能给出页码出处的问答助手。重点不在"接个模型"，而在**文档清洗、切块策略和可评测性**。

> **两个版本**：`v1-rag` 是纯检索问答；`v2-agent` 在它外面加了一层工具调用（查内容 / 列章节 / 存笔记），从"能回答"变成"能办事"。原有检索链路一行未改。

## 架构

```
离线建库（跑一次）                          在线问答（每次请求）
PDF → pypdf 抽取文字                      提问 → BGE 向量化
    → 剔除页眉页脚模板行                        → Chroma 余弦检索 top-k
    → 按小节聚块 + 折行合并                     → 组装 Prompt（只依据资料）
    → BGE-small-zh 向量化                      → DeepSeek 流式生成
    → 写入 Chroma（带小节 / 页码元数据）        → 回答附 [小节 p.页码]
```

## 快速开始

```bash
# 建独立虚拟环境（不要装到全局 Python）
python -m venv .venv
.venv\Scripts\activate          # Windows；macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 1) 配置密钥（不要写进代码）
cp .env.example .env      # 填入 DEEPSEEK_API_KEY
set DEEPSEEK_API_KEY=sk-xxx        # Windows cmd
# export DEEPSEEK_API_KEY=sk-xxx   # bash

# 2) 建库（首次会下载 BGE 模型约 100MB，走 hf-mirror）
python ingest.py

# 3) 命令行问答
python rag.py

# 4) 网页界面
streamlit run app.py

# 5) 评测（不带 --llm 只评检索，不需要 Key）
python eval.py

# 6) 消融实验：建一个不清洗的对照组，对比清洗收益
python ingest.py --raw
python eval.py --collection courseware_ch7_raw --k 1

# 7) Agent（v2）：带工具调用的命令行
#    先启动用药后端（localhost:8080），并在 .env 配好 MED_PASSWORD
python -m agent.main
#    · 问「我今天要吃什么药」→ 调 get_today_reminders（真实 HTTP 接口）
#    · 问「数据库设计分几步」→ 调 search_courseware（走 RAG）
#    · 说「20 点那个已服」→ 先问确认，再调 confirm_reminder

# 8) 跑测试（假模型，不消耗 API）
python -m pytest tests -q
```

语料放 `data/`，**自动识别 PDF / DOCX / Markdown / TXT**，支持多份混放一起建库。

> - 仓库里**不包含 PDF 本体**（课件有版权，不适合公开分发），请自备文件放进 `data/` 后运行 `python ingest.py`。
> - DOCX 的 `Heading` 样式会被转成 `## 标题`，因此同样能切出小节；表格按行抽成 `单元格 | 单元格`。
> - 非 PDF 没有真实页码，按每 40 行切一个「虚拟页」，引用显示为 `p.1`、`p.2` 这类位置块。
> - 短文档（FAQ、说明页）会自动把碎块门槛从 120 字降到 40 字，避免内容被过滤空。

## v2：从 RAG 到 Agent（工具调用层）

RAG 只有一条路：**总是**检索 → 生成，只能回答，不能办事。v2 在它外面加了一层"先判断该做什么"，四个工具跨两类数据源：

| 工具 | 数据源 | 作用 | 是否走模型 |
|---|---|---|---|
| `search_courseware` | Chroma 向量库 | 查课件知识，复用原 RAG 链路 | 是（检索 + 生成） |
| `get_today_reminders` | Spring Boot `/api/reminders/today` | 查今日服药提醒 | 否（纯接口） |
| `get_recent_records` | Spring Boot `/api/records` | 查最近服药记录 | 否（纯接口） |
| `confirm_reminder` | Spring Boot `/api/reminders/{id}/confirm` | 标记已服 / 稍后 / 跳过（**写操作**） | 否（纯接口） |

**同一个 Agent 同时接两种后端**：一个走向量检索（非结构化文档），三个走 REST 接口（结构化数据 + JWT）。这正是"换功能只换工具，不换骨架"的验证。

### 接真实接口要处理的三件事

1. **JWT 登录与缓存**：`agent/backend.py` 首次调用登录拿 token，之后复用（加锁避免并发重复登录）。课件工具是本地函数调用，没有身份这一层。
2. **字段归一化**：后端返回 `{code, message, data:[{medicineName, mealRelation:2, status:"TRIGGERED"}]}`，工具转成 `{药品, 餐时:"餐后", 状态:"已触发"}`，模型读起来更准，不会把 `code` 当业务字段念。
3. **合规红线**：提示词明确"只陈述记录事实，不给用药建议、不判断相互作用、不推荐剂量"，遇到这类问题固定回复"请咨询医生或药师"。这对应毕设里"系统不做药事顾问"的边界。

### 主循环（`agent/loop.py`）

```
读用户输入 → 带 tools 调 DeepSeek
    ├─ 没有 tool_calls → 直接返回答案
    └─ 有 tool_calls → 执行工具 → 结果回填 messages → 再调一次
         （最多 5 轮，防死循环）
```

### 四个护栏

| 护栏 | 实现 | 防什么 |
|---|---|---|
| 写操作确认 | `confirm_reminder` 前弹确认，拒绝则不发请求 | 模型擅自动用户数据 |
| 无证据拒答 | 复用 `is_low_confidence()`，`found=false` 时不编 | 拿无关片段硬答 |
| 工具异常降级 | `try/except` 转成 `{"error": ...}` 回填 | 一个工具挂了整轮对话崩溃 |
| 最大轮数 | `MAX_STEPS = 5` | 模型反复调工具死循环 |

## 关键设计（面试可讲的部分）

**1. 页眉页脚自动识别**
课件每页都有同一行页眉 `An Introduction to Database System`，94 页里出现 95 次。这类文本会进入几乎每个 chunk，导致「任何问题都能匹配到它」，是很典型的噪声特征污染。
处理方式：统计所有行在页面间的出现频率，超过页面数 50% 的行判定为模板行并剔除。本项目剔掉 1 行，原始 15,418 字符降到清洗后的可用文本。

**2. 按小节聚块，而不是固定字数硬切**
用正则识别 `7.1` / `7.1.1` 这类标题，把同一小节下的连续页合并成一块，元数据保留 `section` 和 `pages`。好处是引用能精确到「7.2.3 数据字典 p.40-47」，而不是只给一个页码。

**3. 折行合并**
PDF 里一句话常被排版拆成两三行（`构造（设` / `计）优化的…`）。规则：上一行没有句末标点、且本行不是列表项时接回上一行；短行用「：」「；」分隔，避免两句粘死。

**4. 碎块过滤**
纯目录页、只有图注的页面会切出几十字的碎片，对检索只增噪不增信。小于 120 字的块直接丢弃；文档总体不足 3000 字时门槛自动降到 40 字，避免短文档被切空。

**5. 多格式加载**
按扩展名分发：PDF 用 `pypdf`；DOCX 用 `python-docx`，把 `Heading` 样式还原成 `## 标题`、表格按行拍平成 `单元格 | 单元格`；MD/TXT 直接按行读。非 PDF 按每 40 行切「虚拟页」，让引用仍有位置信息。

**6. BGE 的查询前缀**
中文 BGE 模型检索时，query 建议加指令前缀（`为这个句子生成表示以用于检索相关文章：`），否则口语化查询的召回会下降。
⚠️ **已知问题**：前缀已在 `config.QUERY_PREFIX` 定义，但 `RagEngine.retrieve()` 目前直接用了原句，**尚未接入**。这是 v2 评测里「0.462 那条被误拒」的疑似原因之一，修复后需重新标定阈值。

**7. 为什么不用 DeepSeek 做向量化**
DeepSeek 只提供对话/推理接口，没有 embedding 模型。所以向量化用本地 `BAAI/bge-small-zh-v1.5`（fastembed + onnxruntime，CPU 可跑，约 100MB），DeepSeek 只负责生成。

**8. 相似度门控（拒答）**实测文档内问题 top1 相似度 ≥ 0.602，文档外问题 ≤ 0.495，中间有明显空档。因此取阈值 0.55：**top1 低于阈值时不调用模型**，直接返回「资料中未找到相关内容」，既避免拿无关片段硬答，也省一次 API 调用（实测响应从 1.2s 降到 0.00s）。阈值可用 `RAG_MIN_SCORE` 覆盖。

## 评测结果

### v1：12 条原文型问题（历史数据）

| 指标 | 值 |
|---|---|
| hit@4 | 100%（12/12） |
| hit@1 | 100%（12/12） |
| MRR | 1.000 |
| 回答覆盖关键词 | 12/12 = 100% |
| 检索延迟 | 预热后中位数 8 ms；冷启动（含模型加载）首条约 140 ms |
| 端到端回答延迟 | 1.0 ~ 2.0 s（deepseek-chat，流式首字约 0.8 s） |
| 语料 | 94 页 → 14 个块 / 9,540 字 |

**消融实验：清洗是否有效**

用同一份 PDF 建两个集合，对照组 `ingest.py --raw` 关掉页眉剔除与折行合并：

| 配置 | 块数 | hit@1 | hit@4 | MRR |
|---|---|---|---|---|
| 不清洗（raw） | 18 | 91.7% | 100% | 0.958 |
| 清洗 + 折行合并 | 14 | **100%** | 100% | **1.000** |

差的那一条，正是被页眉噪声挤掉正确块的问题。语料小，差距不夸张，但方向明确：**清洗让 top1 从 11/12 变成 12/12**。

**拒答行为**：

| 提问 | top1 相似度 | 结果 |
|---|---|---|
| 索引优化有哪些策略？ | 0.495 | ✅ 门控直接拒答，0.00s |
| 期末考试重点是什么？ | 0.426 | ✅ 拒绝编造考试范围 |
| 数据库设计有哪些典型方法？ | 0.794 | ✅ 正常回答（未被误拒） |

> 注意：这 12 条是按课件原文措辞出的，指标偏乐观。所以 v2 把评测改成分层的。

### v2：分层评测（20 正样本 + 8 负样本）

`python eval.py`（纯检索，不需要 Key）：

| 指标 | 值 |
|---|---|
| hit@4（仅 L1/L2） | 100%（16/16） |
| MRR（仅 L1/L2） | 0.969 |
| L3 证据覆盖率 | 100% |
| **负样本拒答准确率** | **87.5%（7/8）** |
| **阈值余量 gap** | **-0.169（区间重叠，不可分）** |
| 检索延迟 | 均值 33 ms / P50 6 ms |

| 层 | 类型 | 条数 | 结果 |
|---|---|---|---|
| L1 | 原文型（照课件措辞） | 10 | 100% 命中 |
| L2 | 改写型（口语/同义） | 6 | 100% 命中，但一条仅 0.462 |
| L3 | 组合型（跨小节） | 4 | 覆盖率 100% |
| L4 | 负样本（课件里没有） | 8 | 拒答 87.5% |

**这一版才暴露出真问题**：

1. 「E-R图合到一起会打架吗？」top1 = **0.462**，低于阈值 0.55——检索其实找对了块，真实问答却会被门控拦掉（**该答的被拒**）。
2. 「数据库备份有哪几种方式？」top1 = **0.630**，高于阈值——命中 7.1.2，因为课件里讲「数据的收集、整理、组织」，和"备份"语义相近（**该拒的答了**）。

根因不是阈值没调好，是**向量只判断"意思像不像"，判断不了"主题是不是同一个"**。后续两条路：补上 BGE 查询前缀（可能抬高 L2 低分题），以及在向量之外加一路 BM25 关键词检索做融合。

## 已知限制

- **阈值在正负样本上重叠**：正样本最低 0.462、负样本最高 0.630，当前 0.55 必然一边误拒、一边误答（详见 v2 评测）。
- **BGE 查询前缀未接入**：`QUERY_PREFIX` 已定义但 `retrieve()` 未使用，口语化查询的召回未优化。
- **块之间零重叠**：长小节被 1200 字上限切开后，答案跨块时可能两边都不完整。
- **图片内容检索不到**：课件里的 E-R 图、模式图是图片，`pypdf` 只能拿到图注，问「图 7.3 画了什么」会答不出。
- **符号字体导致列表项粘连**：部分项目符号是私有区字符，抽出来变空格，合并后会出现「存取效率高数据库存储空间的利用率高」这种粘连。彻底解决要换 PyMuPDF 拿坐标信息。
- **只做单轮检索**：多轮追问里的指代（「它有什么特点」）需要 query 改写，尚未实现。
- **扫描件不支持**：无文字层的 PDF 需要先 OCR。
- **DOCX 的合并单元格会重复文本**：同一格跨列时 `python-docx` 会返回多份，表格抽取可能出现重复；页码也是虚拟块号，不是 Word 的真实页码。

## 后续可以做的

1. 混合检索：BM25（关键词）+ 向量，用 RRF 融合，缓解专有名词召回差。
2. rerank：`bge-reranker-base` 对 top-20 重排，换取精度。
3. 多轮改写：把「它」补全成实体再检索。
4. 换 PyMuPDF 抽取布局，修复列表粘连。
5. Docker 化 + 简单的检索命中率回归测试。
